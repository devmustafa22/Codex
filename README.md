# مدار — مساحتك للنمو 🌿

داشبورد شخصي عربي لتنظيم المهام وتطوير المهارات وتوثيق الأنشطة، مع تقويم أسبوعي وشهري وسنوي. هذه النسخة تضيف **حساباً باسم مستخدم وكلمة مرور، وحفظاً سحابياً عبر Supabase**، وتصميماً متجاوباً للهاتف.

كود الواجهة والخادم مرفق. تفعيل الحسابات الحقيقية يحتاج مشروع Supabase وإعدادات الاتصال ونشر قاعدة البيانات ودالة تسجيل الدخول؛ إعداد الكود لا ينشئ حساب استضافة أو ينشر الموقع تلقائياً.

## التقنيات المستخدمة

| التقنية                       | دورها في المشروع                                                |

| TypeScript                    | تعريف البيانات والمساعدة على اكتشاف أخطاء التعديل               |
| Vite                          | تشغيل المشروع أثناء التطوير وبناء ملفات الاستضافة               |

| Supabase Auth                 | إنشاء الحسابات، كلمات المرور، جلسة الدخول، واسترجاع كلمة المرور |
| PostgreSQL في Supabase        | حفظ مهامك ومهاراتك ومواعيدك وأنشطتك في السحابة                  |
| Row Level Security            | ربط قراءة البيانات بالحساب الذي يملكها                          |
| Supabase Edge Function        | تسجيل الدخول باسم المستخدم بدون نشر قائمة المستخدمين أو بريدهم  |

الواجهة تُنشر على **Cloudflare Workers Static Assets**؛ الحسابات والبيانات تبقى في **Supabase**. تغيير جهازك لا يحتاج نقل البيانات عندما تسجّل بالحساب نفسه وتكتمل المزامنة. إعداد النشر موجود في `wrangler.jsonc`، واسم مشروع Cloudflare المطابق له هو `codex`.

## التشغيل على Windows وVS Code

إذا هذه أول تجربة لك: ابدأ بملف [START-HERE.md](START-HERE.md). على Windows يمكنك فتح **START-MADAR.cmd** بنقرتين بعد فك الضغط؛ ينزّل ملفات التشغيل عند الحاجة ويفتح الموقع بالمتصفح. تحتاج Node.js 22 أو أحدث، ولا تحتاج كتابة أوامر.

1. فك ضغط المشروع، وافتح في VS Code مجلد `madar` الذي يحتوي ملف `package.json`.
2. ثبّت **Node.js 22 أو أحدث** إذا لم يكن موجوداً.
3. افتح **Terminal → New Terminal** داخل هذا المجلد، ثم نفّذ:

   ```powershell
   npm.cmd ci
   npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort --open
   ```

هذه الأوامر تفتح الموقع في متصفح جهازك. ملف `index.html` يشغّل React من `src/main.tsx`، لذلك طبيعي أن يبدو صغيراً؛ الشاشات والكود موجودة داخل `src`.

يمكن أيضاً الضغط على **F5** واختيار «مدار: افتح في Chrome» أو «مدار: افتح في Edge». إعدادات `.vscode` تثبّت الاعتماديات ثم تشغّل الموقع، ولا تحتاج إضافة خارجية. أوقف الخادم السابق على المنفذ 5173 قبل تشغيل نسخة أخرى، ولإيقافه اضغط `Ctrl+C` في طرفيته.

في macOS أو Linux استخدم `npm` بدلاً من `npm.cmd`.

## تفعيل الحساب والحفظ السحابي

اتبع [دليل إعداد Supabase خطوة بخطوة](docs/cloud-setup.md). الخطوات الأساسية:

1. أنشئ مشروع Supabase مجاني وطبّق ملفات الترحيل الموجودة في `supabase/migrations` بالترتيب.
2. انشر دالة `username-login` وحدّد عناوين المواقع المسموح لها باستعمالها.
3. انسخ `.env.example` إلى `.env.local` وأضف رابط المشروع ومفتاحه **العام**:

   ```dotenv
   VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_PUBLIC_KEY
   ```

4. اضبط عناوين تأكيد البريد واسترجاع كلمة المرور في Supabase، ثم أعد تشغيل Vite.

المفتاح العام مخصص للمتصفح. لا تستخدم `service_role` أو `sb_secret_` في الواجهة. ملف `.env.local` مستبعد من Git؛ لا ترفعه إلى المستودع.

إنشاء الحساب يحتاج اسم مستخدم من 3 إلى 24 حرفاً إنكليزياً أو رقماً أو `_`، واسم عرض يدعم العربية، وبريداً إلكترونياً، وكلمة مرور من 10 أحرف على الأقل تحتوي حرفاً ورقماً. اسم المستخدم يُحفظ بأحرف صغيرة. تسجيل الدخول يقبل اسم المستخدم أو البريد؛ البريد ضروري لتأكيد الحساب واسترجاع كلمة المرور.

عند غياب إعدادات Supabase تظهر شاشة الإعداد، ويمكن اختيار **التجربة المحلية** لاستكشاف المشروع. هذا الوضع يحفظ في المتصفح ويعرض بيانات المثال، ولا يوفّر حساباً أو مزامنة سحابية.

## إدارة حسابات المستخدمين

لوحة **إدارة الحسابات** تعرض الحسابات المسجلة وتتيح البحث والتوقيف وإعادة التفعيل والحذف المؤكّد. تظهر للأدمن فقط، وصلاحيتها تأتي من قاعدة البيانات. دورك المكتوب في الملف الشخصي لا يمنح صلاحيات الإدارة.

لتفعيلها للحساب الحالي `mustafaasad`، اتبع [خطوات تفعيل الأدمن في Supabase](supabase/dashboard-admin-deploy.md): الترحيل الجديد، ملف منح الصلاحية المنفصل، ثم نشر دالة `account-admin`. لا تنشئ هذه الخطوات حساباً جديداً ولا تغيّر كلمة المرور. تعطي كل عملية صلاحية من الخادم، ويمنع التوقيف الحساب من قراءة مساحته أو حفظها حتى بجلسة قديمة. حسابات الأدمن محمية من التوقيف والحذف.

شرح السلوك في [إدارة الحسابات](docs/account-administration.md)، وخطة المرحلة التالية للاشتراكات والعربية/الإنكليزية في [خارطة الاشتراكات والتوسّع](docs/subscription-roadmap.md). الدفع والواجهة الإنكليزية لم يُفعّلا في هذه المرحلة.

## الشاشات والوظائف

- **نظرة عامة:** خطة اليوم، وقت التعلّم، هدف أسبوعي، نمو المهارات، وتذكيرات.
- **المهام:** لوحة بثلاث حالات أو قائمة، إضافة وتعديل وحذف، أولويات، فلاتر، ومهارة مرتبطة.
- **المهارات:** هدف كلي وأسبوعي بالساعات، رصيد سابق، تقدّم محسوب، وسجل جلسات مرتبط.
- **التقويم:** تفاصيل اليوم، أسبوع وشهر وسنة، مواعيد قابلة للإدارة، ومهام تظهر من دون إدخالها مرتين.
- **سجلّ الرحلة:** تعلّم وعمل وأنشطة شخصية، مدة وملاحظات ومزاج، بحث وتصفية.
- **التحليلات:** وقت فعلي وإنجازات، توزيع المهارات، تقويم نشاط سنوي، ومراجعة أسبوعية.
- **الإعدادات:** الملف الشخصي والأهداف، الوضع الليلي، إدارة الحساب، ونسخ JSON الاحتياطية.
- **إدارة الحسابات:** للأدمن فقط؛ أعداد الحسابات والبحث وحالات التفعيل وإدارة الحسابات، مع حماية المدراء وتأكيد كتابة اسم المستخدم قبل الحذف النهائي.
- **مؤقّت التركيز:** ربط جلسة بمهمة أو مهارة، إيقاف ومتابعة، وحفظ الوقت عند الإنهاء أو اكتمال الجلسة.
- بحث عام مع `Ctrl/⌘ + K`، دعم لوحة المفاتيح، وتنقل مناسب لشاشة الهاتف.
- **حجم الخط:** أربعة أحجام من الإعدادات، تُطبّق مباشرة على صفحات المنصة وتُحفظ مع حسابك السحابي؛ في التجربة المحلية تُحفظ بالمتصفح. النسخ القديمة التي لا تتضمن هذا الاختيار تستخدم الحجم الافتراضي.

## بياناتك والمزامنة

الحساب الحقيقي يبدأ بمساحة فارغة. بيانات النسخة المحلية السابقة وبيانات المثال **لا تُرفع تلقائياً** إلى الحساب. لنقل سجلك السابق، افتح النسخة القديمة وصدّر JSON من الإعدادات، ثم سجّل دخولك في النسخة الجديدة واسترجع الملف من الإعدادات بعد مراجعة البيانات.

التعديلات تظهر فوراً، ثم تُرسل إلى السحابة. راقب حالة الحفظ قبل إغلاق الصفحة أو الانتقال إلى جهاز آخر. إذا انقطع الإنترنت تبقى نسخة استرجاع محلية منفصلة لكل حساب على ذلك المتصفح؛ لا تُعد البيانات محفوظة سحابياً حتى يظهر نجاح المزامنة. إذا عدّل جهازان البيانات نفسها، يعرض التطبيق تعارضاً لتختار النسخة المطلوبة بدلاً من استبدال تغييرات الجهاز الآخر بصمت.

- احتفظ بنسخة JSON دورية، خصوصاً قبل الاسترجاع أو حل تعارض أو تغيير الإعدادات.
- الاسترجاع يتحقق من الإصدار والحقول والتواريخ وروابط المهارات، وحد الملف 5 MB.
- مسح بيانات المتصفح قد يزيل التعديلات المحلية التي لم تصل إلى السحابة.
- تسجيل الخروج ينهي جلسة هذا المتصفح؛ استخدم جلسة خاصة على جهاز مشترك لأن نسخة الاسترجاع المحلية قد تبقى على الجهاز.
- في التجربة المحلية فقط، البيانات مرتبطة بالمتصفح وبعنوان الموقع، وتغيير الجهاز يحتاج تصديراً واسترجاعاً يدوياً.

## حساب التقدّم

وقت المهارة = رصيد التعلّم السابق + دقائق الأنشطة المسجلة المرتبطة بها. النسبة = الوقت ÷ الهدف الكلي، بحد أعلى 100%.

إكمال المهمة يسجّل تاريخ الإنجاز ويؤثر على تحليلات المهام. الوقت المقدّر لا يُضاف إلى وقت التعلّم؛ وثّق الوقت الفعلي عبر النشاط أو مؤقّت التركيز. المواعيد تنظّم وقتك ولا تسجّل حضوراً تلقائياً.

الأسبوع يبدأ يوم الإثنين. تاريخ اليوم حسب منطقة **بغداد**، والتواريخ اليومية محفوظة بصيغة `YYYY-MM-DD` دون تحويلها إلى UTC.

المؤقّت يبقى فعالاً عند التنقل بين الشاشات، لكن الجلسة الجارية لا تُستعاد بعد إعادة تحميل الصفحة أو إغلاق المتصفح؛ أنهِها واحفظها أولاً. اكتمال الجلسة يسجّل نشاطاً واحداً ولا يكمل المهمة تلقائياً.

## تنظيم الكود

```text
src/
  components/       عناصر مشتركة، نوافذ التحرير، البحث، والمؤقّت
  pages/            شاشة مستقلة لكل قسم
  state/            الحالة، الحسابات، الحفظ والمزامنة
  lib/              نماذج البيانات، التواريخ، الحسابات، والتحقق
  styles/           تصميم مشترك، ملف لكل شاشة، واستجابة للهاتف
  App.tsx           هيكل التطبيق والتنقل
  main.tsx          نقطة البداية والخطوط
supabase/
  migrations/       قاعدة البيانات والصلاحيات وحفظ الإصدارات
  functions/        دالة تسجيل الدخول باسم المستخدم
  config.toml       إعداد نشر الدالة
public/             الأيقونة والملفات الثابتة
tests/              سيناريوهات المتصفح
docs/               أدلة الإعداد والنشر ومصادر التصميم
```

ابدأ الألوان من `src/styles/base.css`، وبيانات المثال من `src/lib/seed.ts`. أنواع البيانات في `src/lib/types.ts`، وكل شاشة في ملف مستقل ضمن `src/pages`.

## البناء والتحقق

```bash
npm ci
npm test
npm run test:backend
npm run build
npm run format:check
npm run test:e2e
```

اختبارات المتصفح تستخدم Chromium النظام إذا توفر، وإلا ثبّته بواسطة `npx playwright install chromium`. بناء الواجهة ينتج مجلد `dist`؛ جرّبه محلياً عبر `npm run preview`.

اختبارات `test:e2e` تشمل التجربة المحلية ومكتبة Supabase الفعلية مع طلبات HTTP محاكاة؛ لا تستخدم حسابات حقيقية. فحص SQL على PostgreSQL متاح عبر `npm run test:db` عند توفر Docker وBash.

هذه الفحوص تتحقق من الكود وتجربة المتصفح. اختبار مشروع Supabase المستضاف، وصول رسائل البريد، وعزل حسابين حقيقيين يجب إكماله بعد تفعيل مشروعك وفق [قائمة التحقق في دليل السحابة](docs/cloud-setup.md).

## النشر

أنصح بـ **Cloudflare Workers Static Assets + Supabase Free** للاستخدام الشخصي. [دليل النشر](docs/deployment.md) يشرح ربط GitHub، إعدادات البناء، والحدود المجانية، مع خيار Pages كبديل. دليل Supabase يوضح أيضاً إعداد البريد: خدمة البريد الافتراضية محدودة، وللحسابات العامة تحتاج مزوّد SMTP مناسباً.

مصادر Linear وTodoist وNotion وGitHub وقرارات التصميم موجودة في [بحث التصميم](docs/design-research.md).
