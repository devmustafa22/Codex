# تفعيل الحسابات والحفظ السحابي

الواجهة جاهزة للاتصال بـ Supabase. تحتاج تنفيذ هذه الخطوات مرة واحدة على مشروعك؛ لم يُنشأ مشروع مستضاف أو تُطبّق إعداداته نيابة عنك. ابدأ بمشروع جديد لكي لا تختلط جداول مدار ببيانات تطبيق آخر.

## 1. إنشاء مشروع مجاني

افتح [Supabase](https://supabase.com/dashboard)، وأنشئ مشروعاً ضمن الخطة المجانية. اختر المنطقة الأقرب إليك، واحفظ كلمة مرور قاعدة البيانات في مدير كلمات المرور؛ لا تضعها في كود الواجهة.

من إعدادات المشروع أو نافذة **Connect**، خذ:

- **Project URL** مثل `https://your-project.supabase.co`.
- **Publishable key** الذي يبدأ بـ `sb_publishable_`. يمكن استعمال مفتاح `anon` القديم العام أيضاً.
- **Project reference**، وهو معرّف المشروع المطلوب لربط أداة Supabase CLI.

المفتاح العام يظهر في ملفات الواجهة بشكل طبيعي، والصلاحيات تُفرض في قاعدة البيانات. `service_role` و`sb_secret_` مفاتيح خادم سرّية؛ لا تضعها في `.env.local` أو Cloudflare أو GitHub أو رسائل الدردشة.

## 2. إنشاء الجداول والصلاحيات

من مجلد المشروع، وبوجود Node.js 22، اربط أداة Supabase بالمشروع:

```bash
npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase db push
```

استبدل `YOUR_PROJECT_REF` بمعرّف مشروعك. أداة تسجيل الدخول تفتح المتصفح، وقد يطلب الربط كلمة مرور قاعدة البيانات. أدخل الأسرار في أداة Supabase نفسها. على Windows إذا منع PowerShell تشغيل `npx.ps1`، استخدم `npx.cmd` بدلاً من `npx`.

الأمر الأخير يطبّق ملف `supabase/migrations/202610060001_cloud_accounts.sql`، الذي ينشئ:

- ملف الحساب واسم المستخدم الفريد، بدون قائمة عامة تكشف المستخدمين أو بريدهم.
- مساحة بيانات مستقلة لكل حساب، مع قراءة مقيدة بصاحبها عبر RLS.
- إجراء حفظ يتحقق من رقم الإصدار لمنع الكتابة فوق تعديل صادر من جهاز آخر بدون تنبيه.
- محدّد لمحاولات تسجيل الدخول تستخدمه الدالة من جهة الخادم.

**بديل بدون تطبيق SQL من الطرفية:** افتح **SQL Editor** في Supabase، وانسخ محتوى ملف migration كاملاً ونفّذه مرة واحدة على مشروع جديد. إذا اخترت هذا البديل، لا تُعد تطبيق الملف نفسه بواسطة `db push`؛ أدوات الهجرة تحتاج تسوية سجلها أولاً عند التحويل بين الطريقتين. يبقى نشر دالة اسم المستخدم مطلوباً في الخطوة التالية.

## 3. نشر تسجيل الدخول باسم المستخدم

نفّذ من مجلد المشروع المرتبط:

```bash
npx supabase secrets set ALLOWED_ORIGINS="http://localhost:5173,http://127.0.0.1:5173,https://YOUR_SITE.pages.dev"
npx supabase functions deploy username-login --no-verify-jwt --use-api
```

استبدل عنوان `YOUR_SITE.pages.dev` بعنوان موقعك النهائي. إذا لم تنشر الواجهة بعد، ابدأ بعنوانَي التطوير فقط، ثم أعد أمر `secrets set` بعد معرفة عنوان الاستضافة. الأمر يستبدل قيمة القائمة، لذلك أدرج كل العناوين التي تريد إبقاءها مسموحة.

العناوين هنا **origins**: البروتوكول + النطاق + المنفذ، بدون مسار أو `/` في النهاية. إذا تغيّر نطاق الاستضافة، حدّث القائمة. لا تسمح لكل النطاقات باستخدام `*`.

دالة `username-login` تعمل قبل وجود جلسة مستخدم، لذلك إعداد `verify_jwt=false` مقصود. الدالة تتحقق من كلمة المرور عبر Supabase Auth وتحدّ المحاولات؛ لا تعتمد حماية الحساب على ترويسة JWT قبل تسجيل الدخول. مفاتيح الخادم التي تحتاجها الدالة يوفّرها Supabase في بيئتها، ولا تُضاف إلى الواجهة.

بدون نشر هذه الدالة يمكن لتسجيل الدخول بالبريد أن يعمل، لكن تسجيل الدخول باسم المستخدم لن يعمل.

## 4. إعداد ملف الاتصال المحلي

انسخ `.env.example` إلى `.env.local` في نفس مجلد `package.json`. على Windows يمكن تنفيذ:

```powershell
Copy-Item .env.example .env.local
```

عدّل الملف بالقيم العامة من مشروعك:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_PUBLIC_KEY
```

أوقف Vite بواسطة `Ctrl+C`، ثم شغّله من جديد:

```powershell
npm.cmd ci
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort --open
```

في Cloudflare يجب إضافة المتغيرين إلى إعدادات **البناء** أيضاً؛ ملف جهازك لا ينتقل تلقائياً إلى الاستضافة. تغيير المتغيرات بعد النشر يحتاج إعادة بناء ونشر الواجهة.

## 5. إعداد تأكيد البريد واسترجاع كلمة المرور

في **Authentication → URL Configuration**:

- اجعل **Site URL** عنوان الإنتاج، مثل `https://YOUR_SITE.pages.dev`.
- أضف العناوين التالية إلى **Redirect URLs**، مع استبدال نطاق الإنتاج:

  ```text
  https://YOUR_SITE.pages.dev/
  https://YOUR_SITE.pages.dev/?auth=recovery
  http://localhost:5173/
  http://localhost:5173/?auth=recovery
  http://127.0.0.1:5173/
  http://127.0.0.1:5173/?auth=recovery
  ```

في إعدادات مزوّد **Email**، أبقِ تأكيد البريد مفعّلاً. اضبط حد كلمة المرور في Supabase على 10 أحرف على الأقل أيضاً؛ واجهة مدار تطلب 10 أحرف وحرفاً ورقماً.

المشروع يستعمل PKCE: افتح رسالة تأكيد البريد أو استرجاع كلمة المرور **في نفس المتصفح الذي بدأت منه العملية**، لأن جزء التحقق محفوظ فيه. إذا طلبت استرجاعاً على الكمبيوتر ثم فتحت الرابط على الهاتف، ابدأ طلب استرجاع جديداً من متصفح الهاتف. بعد تأكيد البريد تستطيع تسجيل الدخول بشكل عادي من أجهزتك الأخرى.

التطبيق يستخدم رابط التأكيد الافتراضي الذي ينشئه Supabase. إذا عدّلت قوالب البريد، حافظ على رابط `{{ .ConfirmationURL }}`؛ لا تستبدله بمسار خادم مخصص لم ينفّذه هذا المشروع.

## 6. وصول رسائل البريد

خدمة SMTP الافتراضية في Supabase مخصصة للتجربة وتُرسل فقط إلى عناوين أعضاء فريق المشروع، وبحدود إرسال منخفضة. هذا قد يفسّر عدم وصول رسالة التأكيد إلى بريد آخر، حتى لو كان كود الواجهة صحيحاً.

لإنشاء حسابك الشخصي أولاً، استخدم بريد حسابك العضو في فريق Supabase. إذا تريد فتح التسجيل لمستخدمين آخرين، اضبط **Custom SMTP** لدى مزوّد بريد مناسب؛ راجع [دليل Supabase الرسمي](https://supabase.com/docs/guides/auth/auth-smtp) وخطة مزوّد البريد قبل الاعتماد عليه. الاستضافة وقاعدة البيانات المجانيتان لا تضمنان بريد إرسال عاماً مجانياً بلا حدود.

أدخل بيانات SMTP السرّية في إعدادات Supabase فقط. أبقِ تأكيد البريد فعالاً عند النشر العام، واختبر التأكيد والاسترجاع قبل اعتماد الموقع.

## 7. بدء استخدام حسابك ونقل بيانات النسخة السابقة

أنشئ حساباً من شاشة مدار: اسم عرض عربي، اسم مستخدم، بريد إلكتروني، وكلمة مرور. اسم المستخدم من 3 إلى 24 حرفاً إنكليزياً أو رقماً أو `_`، ويُحوّل إلى أحرف صغيرة. بعد تفعيل البريد سجّل باسم المستخدم أو البريد.

الحساب الجديد يبدأ فارغاً. للانتقال من نسخة المتصفح السابقة:

1. افتح النسخة السابقة على نفس العنوان والمتصفح الذي يحتوي بياناتك.
2. من الإعدادات نزّل نسخة JSON واحتفظ بها.
3. افتح النسخة الجديدة، وسجّل بحسابك ثم استرجع النسخة من الإعدادات.
4. انتظر نجاح الحفظ السحابي، ثم جرّب الحساب من جهاز آخر.

لا يرفع التطبيق بيانات التجربة أو بيانات المتصفح السابقة إلى السحابة بدون اختيارك. إذا تعذّر تحميل الحساب ولم توجد نسخة محلية صالحة له، تنتظر المساحة استعادة الاتصال بدل فتح بيانات فارغة قد تستبدل سجلك. الاسترجاع يستبدل بيانات المساحة الحالية؛ خذ نسخة منها أولاً إن كانت تحتوي سجلات مهمة.

## 8. التحقق قبل الاعتماد اليومي

بعد نشر الواجهة وربط مشروعك:

- أنشئ حساباً وفعّل بريده، ثم جرّب تسجيل الدخول باسم المستخدم وبالبريد.
- أضف مهمة ومهارة ونشاطاً وموعداً، وانتظر تأكيد المزامنة. أعد تحميل الصفحة وتحقق من بقائها.
- افتح الحساب نفسه على الهاتف والكمبيوتر، وجرّب التحديث من كل جهاز.
- أنشئ حساباً ثانياً؛ تأكد من أنه يبدأ بمساحة فارغة ولا يعرض سجلات الأول.
- عدّل نفس المساحة من جهازين قبل اكتمال التحديث، وتأكد من ظهور التعارض وخيارات حله. نزّل نسخة احتياطية قبل استبدال إحدى النسختين.
- افصل الإنترنت، وسجّل تعديلاً، ثم أعد الاتصال وتحقق من نجاح إرساله. لا تغلق الصفحة قبل نجاح المزامنة إلا مع الاعتماد على نسخة الاسترجاع المحلية.
- جرّب «نسيت كلمة المرور»، افتح الرسالة في نفس المتصفح، ثم حدّث كلمة المرور وسجّل مجدداً.
- جرّب شاشة الهاتف، فتح النوافذ، لوحة المفاتيح، والتنقل بين الأقسام.

فحوص الكود المحلية لا تثبت وصول البريد أو عمل مشروعك المستضاف قبل إكمال هذه الخطوات. احتفظ بنسخة JSON دورية حتى مع وجود تخزين سحابي.
