## إعداد Workers Static Assets — 7 تشرين الأول 2026

- نجح تثبيت الاعتماديات من ملف القفل بواسطة `npm ci` بعد إضافة Wrangler، وبقيت إصدارات جميع الاعتماديات السابقة كما هي.
- نجح `npm run build` بعد إضافة إعداد Workers Static Assets: بناء TypeScript وVite 6.4.4.
- نجح `wrangler deploy --dry-run --outdir=.wrangler/dry-run` بواسطة Wrangler 4.148.0؛ قرأ 32 ملفاً من `dist` وانتهى برمز خروج 0.
- نجح تشغيل `wrangler dev --local`: استجابة HTTP 200 للصفحة العربية وملفات JavaScript وCSS والأيقونة، وإرجاع الصفحة للمسار الداخلي عبر إعداد SPA. أُوقف الخادم بعد الفحص. ظهرت رسالة تعذّر جلب بيانات `Request.cf` الاختيارية واستُخدمت القيم الافتراضية؛ لم تؤثر على خدمة الملفات.

فحص `dry-run` يراجع إعدادات النشر والملفات محلياً؛ لم ينشر موقعاً أو يختبر حساب Cloudflare الفعلي. تبقى تجربة رابط الإنتاج، تسجيل الدخول، والحفظ على Supabase مطلوبة بعد النشر.

## تحديث إدارة الحسابات — 7 تشرين الأول 2026

- نجح بناء TypeScript وVite بعد إضافة الإدارة وشاشة فحص حالة الحساب، مع تحميل صفحة الإدارة عند الحاجة.
- نجح `npm test`: 125 اختباراً، تشمل عزل الحسابات والتحقق من صلاحيات الخادم واستجابات الإدارة وحالات النتيجة غير المؤكدة.
- نجح `npm run test:backend`: 37 اختباراً؛ 10 لتسجيل الدخول و27 لإدارة الحسابات، تشمل رفض تزوير الهوية، صلاحيات الأدمن، الحذف المؤكّد، وتعامل الحظر والحذف مع فشل الشبكة.
- نجحت 30 تجربة متصفح: 12 للنسخة المحلية، و6 للحسابات السحابية السابقة، و12 للإدارة والتوقيف والجلسات القديمة وعرض الهاتف بعرض 360 بكسلاً. تستخدم فحوص الحسابات مكتبة Supabase الفعلية مع بديل HTTP؛ ليست عمليات على حسابات المستخدم الحقيقية.
- نجح فحص PostgreSQL 17 الفعلي: منع المستخدم العادي من إجراءات الإدارة، رفض ترقية الدور من بيانات التسجيل، منع القراءة والحفظ بجلسة موقوفة، استعادة الوصول، حماية المدراء، تسلسل العمليات المتزامنة، بقاء الحذف غير المؤكد محجوزاً، حذف البيانات المرتبطة، وسلامة سجل العمليات.
- نجح تشغيل ملف منح الإدارة `promote-owner.sql` واختبار تكراره، ورفض تشغيله من دور غير مسموح أو لحساب مفقود أو موقوف أو ذي عملية معلّقة.
- نجح `deno check` للدالة المكونة من ملفات ونسختها الموحدة لمحرر Supabase، ونجح فحص التنسيق.

هذه نتائج بيئة التطوير. الحساب الفعلي `mustafaasad` لا يحصل على صلاحية الأدمن بمجرد نشر الواجهة؛ يحتاج تطبيق الترحيل وملف منح الصلاحية ونشر دالة `account-admin` في مشروع Supabase كما في [دليل التفعيل](../supabase/dashboard-admin-deploy.md). تبقى تجربة حساب عادي على الموقع المنشور مطلوبة بعد التفعيل. لم ننفّذ توقيفاً أو حذفاً على حسابات المستخدم الحقيقية خلال هذه الفحوص.

- نجح بناء TypeScript وVite، وفحص التنسيق، والاختبارات الوحدوية الـ125 وتجارب المتصفح الـ30 الموجودة.
- نجح فحص إضافي للعرض عند تكبير الخط إلى 150% على الصفحات السبع بأبعاد 360 و390 و1024 و1440 بكسلاً: 28 حالة بلا تمرير أفقي للصفحة، مع فحص الاختيار بلوحة المفاتيح وبقاء الحجم بعد إعادة التحميل.
- نجح فحص إعداد الخط عبر مكتبة Supabase مع محاكاة HTTP: الحفظ في بيانات المساحة، إعادة تحميله، واستعادة الاختيار في سياق متصفح ثانٍ. هذا فحص لمحاكاة جهازين، وليس اتصالاً بحساب حقيقي.
- روجعت صور الهاتف عند أكبر حجم: الإعدادات، لوحة اليوم، محرر المهمة، إدارة الحسابات ونافذة تأكيد الحذف. بقيت الأزرار قابلة للوصول.

نشر الواجهة المحدّثة على Cloudflare والتحقق منها على الموقع الفعلي يظلان منفصلين عن هذه الفحوص المحلية.

الفحوص السحابية تستخدم بديلاً لطلبات HTTP، ولا تثبت تسليم البريد أو اتصالاً حقيقياً بقاعدة الإنتاج. الرسائل الثابتة تتبدّل فوراً؛ بعض رسائل الخطأ المركّبة التي ظهرت قبل التبديل تحتفظ بلغتها حتى إعادة المحاولة. لم يتغير منطق الصلاحيات أو الإيقاف والحذف في الخادم.

خطة الاشتراكات والترويج موثقة في [دليل الإطلاق](madar-launch-plan.md)، ولم تُنفّذ بوابة دفع أو اشتراكات مالية. تعذّر التحقق المباشر من قوائم قبول البائعين ورسوم بوابات الدفع بسبب رفض الاتصال بالشبكة؛ يجب تأكيد أهلية صاحب المشروع المقيم في العراق ووسيلة السحب قبل التكامل.
